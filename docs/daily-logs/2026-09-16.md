## 🛠️ Work Done & Changes

1. **Trigger Endpoint Added**:
   - Discovered that the Calendar UI path had no direct runner trigger if a job was already due upon scheduling.
   - Added `app/api/schedules/trigger/route.ts` to silently forward execution requests to `/api/schedules/runner` with the internal `CRON_SECRET` without exposing secrets to the browser.
   - Connected trigger to `components/content-preview-modal.tsx`.

2. **Database Driver & SQL Statement Splitting**:
   - Discovered that Neon's HTTP driver failed on multi-statement `schema.sql` execution with `cannot insert multiple commands into a prepared statement`.
   - Created `splitSqlStatements()` in `server/db/client.ts` to strip comments and cleanly split queries into sequential executions. Covered by regression unit tests.

3. **Neon Environment Variable Precedence**:
   - `server/db/client.ts` updated to check `POSTGRES_DATABASE_URL` (Neon-Vercel integration default) first, falling back to `DATABASE_URL`.
   - Created `/api/schedules/init-db` and successfully initialized `automation_jobs` and `automation_runs` tables on the live database.

4. **Queue Backfill Execution**:
   - Created `POST /api/schedules/backfill-queue` to backfill missing queue jobs for pre-existing Airtable `Scheduled` rows.
   - Executed backfill: 24 rows newly enqueued in Production, 2 fresh rows already present, 1 past-due row skipped (`CTA-STORY-TL-1`).

5. **Release & Pull Request**:
   - Merged to `main` via PR #7 (`codex/calendar-runner-trigger`) and verified production deployment.
