## 🛠️ Work Done & Changes
1. **Root cause**: every planned time in `lib/content-data.json` was 8 hours early (timezone-dependent `Date` parsing from `xlsx`). It affected all months (91 days changed since `55a65a8`), not only October. See [[troubleshooting/calendar-import-timezone]].
2. **Parser fix**: `lib/workbook.ts` and `scripts/parse-calendar.mjs` read raw Excel serials (`cellDates: false`), convert time fractions to `H:MM`, and detect the year via `SSF.parse_date_code`. Planned statuses starting with "Scheduled" are normalized to "To Do".
3. **Data regenerated** from the latest `oct-calendar.xlsx` (now in `data/`): "One Light at a Time" name, correct times, chronological day keys. Output is identical under `TZ=UTC` and `TZ=Asia/Manila`.
4. **Tests**: added time and status regression tests in `tests/calendar-import.test.ts`.
5. **Live read-only check** (local app `GET /api/schedules`, no writes): scheduled items in Airtable for Oct 1–2 carry the early times.

   - 2026-10-02 Stories Collection Category (Pendant Light) 01:00 (sheet says 9:00)
   - 2026-10-02 Stories Product Closeup w/ specifications (Chandelier) 05:00 (sheet says 13:00)
   These were NOT changed. Rescheduling is a live provider mutation and needs the operator's go-ahead.
6. Verification: `npm test` (12 files, 110 tests), `npm run typecheck`, `npm run build` pass locally. This does not prove any live publication.
