## 🛠️ Work Done & Changes
1. **Root Cause Analysis**:
   - Discovered that pipelines write captions into `Caption Generated`, whereas legacy calendar schedule readers looked only for `Generated Caption` or `Caption`.
   - Identified that Airtable lookup/rollup fields return single-element arrays (`["..."]`), which caused strict string-only checks to evaluate to false and return empty strings.
   - Identified that only Virtual Staging Reel currently calls `generate_caption()` in the backend automation, while other Feeds/Reels have not been wired yet to write captions before marking records Done/Complete.
2. **Unified Read-Side Extraction**:
   - Enhanced `extractCaption` in [lib/caption.ts](file:///c:/Users/User/Downloads/Marketing%20Output%20UI/lib/caption.ts) and [lib/output-media.ts](file:///c:/Users/User/Downloads/Marketing%20Output%20UI/lib/output-media.ts) to support all column aliases (`Caption Generated`, `Generated Caption`, `Caption`, `Post Caption`, `Final Caption`, `Copy`, `Reel Headline`, `Headline`).
   - Added automatic unwrapping for single-element Array/Lookup values from Airtable.
   - Wired `lib/schedules.ts` and `app/api/content-outputs/route.ts` to use the unified helper.
3. **Plan Documentation**:
   - Documented the backend plan in [docs/superpowers/plans/2026-10-29-auto-caption-all-feeds-and-reels.md](file:///c:/Users/User/Downloads/Marketing%20Output%20UI/docs/superpowers/plans/2026-10-29-auto-caption-all-feeds-and-reels.md) and on `marketing-automation`.
4. **Verification**:
   - Added unit test cases to [tests/caption.test.ts](file:///c:/Users/User/Downloads/Marketing%20Output%20UI/tests/caption.test.ts) covering all aliases and array lookups.
   - Ran `npm test` (all 159 tests passed across 16 files).
