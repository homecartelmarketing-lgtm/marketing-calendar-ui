# Session Log: 2026-11-03 — Airtable Schedule & Status Sync Resilience (HTTP 422 Root Cause Resolution)

#daily-log #airtable #scheduling #status-sync #resilience #vitest #graphify #obsidian

---

## 🎯 Goals & Objectives
- Investigate and resolve HTTP 422 errors encountered when scheduling or updating status in the Marketing Output UI:
  1. `Scheduling Failed: Airtable could not save the complete schedule change (HTTP 422)` on One Part Per Room (`RKV-REEL-SET-6` in `tbldk5nac1UeYHd77`).
  2. `Failed to update status: {"status":"error","error":"Airtable could not save the complete change"}` on Virtual Staging (`tblPYG5Ed4XURecu6`) when toggling `For Manual` or `Completed`.
- Perform full Airtable Base metadata audit across all pipeline tables.
- Add `"Done"` fallback when resetting status to Completed for tables that define `Done` instead of `Completed`.
- Add graceful fallback for date clearing (`For Manual`, `Discard`, `Completed`) on tables that do not have date columns.
- Maintain strict schedule timestamp requirements (`Scheduled` must always write a timestamp and throw if missing).

---

## 🛠️ Work Done & Changes
1. **Metadata Audit Across Airtable Base (`appDM0jUDsaiThtR3`)**:
   - `tbldk5nac1UeYHd77` (One Part per Room): Contains `Date and Time Scheduled`, but `Status` choices only had `["Standby", "In progress", "Complete", "Done", "For Manual", "Posted"]`. The choice **`Scheduled`** was completely missing, causing Airtable to reject status writes with `422 INVALID_MULTIPLE_CHOICE_OPTIONS`.
   - Identified tables missing `Date and Time Scheduled` column: `tbl026zbECJJ9FRfj` (Chandelier Moodboard Reel), `tblqXkdDw4O7hxJS4` (House Tour Reel), `tblDa5UOTUTlU1Xxy` (This Mood Every Night).
2. **Schedule Writer Resilience (`server/airtable/write-schedule.ts`)**:
   - **`"Done"` Status Fallback**: Expanded candidate statuses for normalized `Completed`:
     ```typescript
     const statuses = normalizedStatus === "Completed"
       ? ["Completed", "Done", "Complete"]
       : [normalizedStatus]
     ```
   - **Graceful Date-Clearing Fallback**:
     ```typescript
     const dateFields = scheduledAt
       ? ["Date and Time Scheduled", "Date and Time"]
       : clearDate
         ? ["Date and Time Scheduled", "Date and Time", undefined]
         : [undefined]
     ```
     When clearing dates on tables without date columns, if both `Date and Time Scheduled` and `Date and Time` reject with `UNKNOWN_FIELD_NAME`, it falls back to `undefined` (updating status alone).
   - **Strict Schedule Safety Preserved**: For `scheduledAt`, `dateFields` strictly requires `Date and Time Scheduled` or `Date and Time`, ensuring scheduled jobs are never created without timestamps.
3. **Automated Testing (`tests/schedule-writes.test.ts`)**:
   - Added test: `falls back to 'Done' when table rejects 'Completed' with INVALID_MULTIPLE_CHOICE_OPTIONS`.
   - Added test: `clears date gracefully by falling back to status-only when table lacks date fields for 'For Manual'`.
   - Verified that `still rejects 'Scheduled' when table lacks date fields` remains enforced.
   - All 11 tests in `tests/schedule-writes.test.ts` passed.
4. **Verification**:
   - `npm test`: 16/16 test files passed, 169 tests green.
   - `npm run typecheck`: 0 errors.
   - `npm run build`: Turbopack build succeeded.
