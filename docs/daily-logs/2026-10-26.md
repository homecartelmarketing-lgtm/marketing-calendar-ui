# Session Log: 2026-10-26 — Content Calendar Persistent Import

#daily-log #calendar #xlsx #postgres

---

## 🎯 Goals & Objectives
- Make an uploaded monthly calendar the real source of truth instead of a hard-coded seed file.
- Keep previously imported months when a new month is imported.
- Remove the hard-coded October month selection in the import flow.

---

## 🛠️ Work Done & Changes
1. **Store**:
   - Added `calendar_months` to `server/db/schema.sql` (one row per month, JSONB days).
   - Added `server/calendar/store.ts` with `loadCalendar`, `saveCalendar`,
     `resolveStorageMode`, and `CalendarStorageUnavailable`.
   - Postgres in production; in-memory in dev/test; production without a database URL fails closed (503).
   - Re-importing a month replaces that row only. Months absent from the upload are untouched.
2. **API**:
   - Added `GET`/`POST /api/calendar` (`app/api/calendar/route.ts`), 4 MB upload cap.
   - Uploads are parsed server-side with the existing `lib/workbook.ts` and `lib/csv.ts` parsers
     (timezone behavior unchanged).
3. **UI**:
   - `components/content-calendar.tsx` loads saved months on mount, merges them over the seed,
     opens the newest saved month, and refreshes after an import.
   - Month selection uses `lib/calendar-months.ts::pickImportTargetMonth`:
     earliest newly imported month, else the latest imported month. No month is hard-coded.
   - `components/calendar-nav.tsx` disables Import until the saved calendar has loaded.
4. **Seed tooling**:
   - `scripts/parse-calendar.mjs` now reads every month-named sheet instead of a fixed
     July–October list, and prints a day count per month.
